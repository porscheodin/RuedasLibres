--Justificación del uso de desplegables (<details> y <summary>)--

1. Divulgación Progresiva (Progressive Disclosure):
   Permite mantener la interfaz limpia y organizada, evitando sobrecargar al usuario
   con bloques extensos de texto secundario (como los 5 pasos de alquiler o recomendaciones).
   El visitante explora solo el contenido que necesita leer en ese momento.

2. Optimización en Dispositivos Móviles (Responsive UX):
   Reduce drásticamente el desplazamiento vertical (scroll infinito) en pantallas pequeñas,
   permitiendo escanear la página de manera rápida y cómoda.

3. Accesibilidad y Estándar Nativo (HTML5):
   Al ser componentes nativos del navegador, ofrecen soporte automático para navegación
   por teclado (Enter / Espacio) y lectores de pantalla (anuncian si está 'abierto' o 'cerrado'),
   sin requerir scripts complejos ni sobrecargar la página con JavaScript.

--BITÁCORA: PROTOTIPO DE RUTA NOCTURNA CON TAILWIND CSS (UTILITY-FIRST)--

1. Construcción del botón en la semana 2 con Bootstrap:
   - En la semana 2 (con Bootstrap 5.3), los botones se implementaron a partir de clases de componentes predefinidos de alto nivel (como .btn en combinación con modificadores de variante visual como .btn-success o .btn-primary) o utilidades de Bootstrap (como .d-inline-block .rounded .bg-success .text-decoration-none .fw-bold .px-4 .py-2).
   - En el enfoque basado en componentes de Bootstrap, la clase .btn agrupa y preconfigura una gran cantidad de estilos CSS de forma fija: display inline-block, line-height, text-align, text-decoration, border, border-radius, padding base, cursor pointer y transiciones para estados de interacción (hover, focus, active). Las clases modificadoras (.btn-success) simplemente aplican los valores de color predefinidos en la paleta del framework.
   - El resultado es muy rápido de maquetar pero viene condicionado por los patrones y decisiones visuales estrictas que Bootstrap define de fábrica.

2. Construcción del botón "Inscríbete" hoy con Tailwind CSS:
   - En Tailwind CSS no existen componentes prefabricados como .btn por defecto. El enlace <a> con texto "Inscríbete" se construyó desde cero combinando clases de utilidad atómicas que mapean directamente a propiedades de CSS puro:
     • Comportamiento de visualización: 'inline-block' para permitir padding y dimensiones respetando el flujo de texto.
     • Espaciado interno (Padding): 'px-8 py-3.5' para definir el área táctil e interactiva del botón.
     • Tipografía y tamaño: 'text-lg font-bold' para darle jerarquía visual y máxima legibilidad como llamado a la acción (CTA).
     • Paleta de color y contraste: 'bg-emerald-500 text-slate-950', garantizando un contraste óptimo (cumplimiento WCAG) y coherencia con la identidad de marca de Ruedas Libres sobre fondo oscuro.
     • Bordes y redondeado: 'rounded-lg' para suavizar las esquinas.
     • Estados interactivos y sombras: 'hover:bg-emerald-400', 'transition-all', 'shadow-lg' y 'hover:shadow-emerald-500/25' para dar retroalimentación inmediata al pasar el cursor o enfocar el elemento.
   - Todo el botón se definió exclusivamente en el atributo class del enlace, sin usar etiquetas <style>, sin atributos style="" en línea y sin requerir clases de Bootstrap ni reglas CSS adicionales.

3. Diferencia clave entre un framework de componentes y uno utility-first:
   - Framework de componentes (Bootstrap):
     Ofrece abstracciones de alto nivel orientadas a componentes listos para usar (.card, .btn, .navbar, .modal). Facilita armar interfaces estándar en minutos, pero restringe la originalidad del diseño y suele provocar que múltiples proyectos se vean visualmente homogéneos. Para personalizarlo fuera de sus variables base, se requiere sobreescribir CSS externo con mayor especificidad o lidiar con selectores complejos.
   - Framework Utility-First (Tailwind CSS):
     Ofrece abstracciones de bajo nivel mediante clases utilitarias atómicas de propósito único (espaciado, colores, tipografía, flexbox/grid, tamaños). No impone ningún componente ni estética prediseñada; otorga libertad total para diseñar interfaces a medida directamente en el HTML con un sistema de tokens de diseño consistente, eliminando la necesidad de inventar nombres de clases BEM, el código CSS huérfano y los conflictos de especificidad.

--BITÁCORA: COMPILACIÓN CON TAILWIND CLI, ANÁLISIS DE OUTPUT.CSS Y BOTONES ACCESIBLES--

1. Experimento de búsqueda en src/output.css:
   - Clase utilizada en el proyecto (ej: .bg-emerald-500):
     Aparece generada en la línea 722 de output.css con su regla CSS completa:
     .bg-emerald-500 {
       --tw-bg-opacity: 1;
       background-color: rgb(16 185 129 / var(--tw-bg-opacity, 1));
     }
   - Clase no utilizada en el proyecto (ej: bg-pink-500):
     No aparece en ninguna parte del archivo output.css (0 resultados de búsqueda).
   - ¿Por qué ocurre esto?
     Tailwind CSS funciona con un compilador Just-In-Time (JIT) y un proceso de "purga" (Tree-shaking). En lugar de compilar miles de clases posibles (lo que crearía un archivo CSS de varios megabytes), el motor escanea los archivos declarados en tailwind.config.js (content: ["./*.html", ...]) y genera exclusivamente el CSS de las utilidades que detecta en el marcado HTML. Si una clase no se usa, nunca se compila ni se envía al navegador, garantizando un peso mínimo para producción.

2. Tres variantes de botones implementadas (nocturna/index.html):
   - Variante 1 (Primaria - Sólida): .bg-emerald-500 con texto oscuro, esquinas redondeadas y sombra para la acción principal ("Inscríbete").
   - Variante 2 (Secundaria - Outline / Borde): border-2 border-emerald-500 con texto esmeralda y hover sutil semitransparente para acciones secundarias ("Ver recorrido").
   - Variante 3 (Terciaria - Ghost / Sutil): Fondo transparente, texto gris claro y hover suave para navegación complementaria ("Volver al inicio").

3. Accesibilidad y estados de foco visible por teclado:
   - Al remover el contorno por defecto del navegador con 'focus:outline-none' (que puede verse tosco e inconsistente entre navegadores), se restauró inmediatamente la accesibilidad por teclado implementando un anillo visible mediante 'focus:ring-2' y la familia de utilidades ring de Tailwind.
   - Para maximizar el contraste sobre el fondo oscuro (#020617), se configuró 'focus:ring-offset-2' y 'focus:ring-offset-slate-950', generando un espacio de separación limpio entre el botón y el anillo iluminado ('focus:ring-emerald-400' / 'focus:ring-slate-400').

   - Formularios accesibles: cada input cuenta con su etiqueta <label> explícita vinculada por for e id, placeholders descriptivos y párrafos de ayuda vinculados inequívocamente mediante aria-describedby.
   - Foco visible garantizado: todos los elementos interactivos suprimen el outline genérico con focus:outline-none e implementan un anillo de alto contraste (focus:ring-2 focus:ring-emerald-400 focus:ring-offset-2 focus:ring-offset-slate-900) para asegurar la visibilidad del foco en navegación por teclado.

--BITÁCORA: MAQUETACIÓN LANDING, ANCLAS Y DECISIÓN GRID VS FLEX--

1. Estructura semántica y contenedor estandarizado:
   - Se estructuró la landing completa utilizando elementos semánticos de HTML5 (<header>, <main>, <section id="..."> y <footer>).
   - Se aplicó la regla del contenedor unificado 'max-w-6xl mx-auto px-6' de forma consistente en el encabezado, en cada una de las cuatro secciones y en el pie de página, garantizando márgenes simétricos y un centrado perfecto sin desbordamientos.
   - El encabezado implementa Flexbox ('flex items-center justify-between') alineando verticalmente el logotipo a la izquierda y la lista de anclas de navegación (#inicio, #rutas, #como-funciona, #inscripcion) junto al botón de llamado a la acción a la derecha.

2. Cuadrícula de rutas (3 columnas):
   - Se distribuyeron las tres tarjetas de rutas en una cuadrícula de tres columnas ('grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-8') adaptativa para móvil, tablet y escritorio.

3. Justificación técnica de Grid para "¿Cómo funciona?":
   - Decisión: Se eligió CSS Grid ('grid grid-cols-1 sm:grid-cols-2 lg:grid-cols-4 gap-6') para los cuatro pasos.
   - Justificación: Los cuatro pasos representan una progresión lineal secuencial (01 a 04) donde es indispensable que cada paso tenga exactamente el mismo ancho (25% en pantallas de escritorio) y mantenga alineación estricta en filas y columnas sin deformaciones. Flexbox distribuiría el espacio de forma más flexible o desigual si el contenido de texto varía entre pasos; Grid, en cambio, asegura una retícula rígida, predecible y responsiva (4 columnas en lg, 2 en sm/md y 1 en móvil).

4. Organización del pie de página (Footer con Flex):
   - Se estructuró en tres bloques autónomos (identidad/misión, navegación rápida y punto de contacto) mediante Flexbox ('flex flex-col md:flex-row justify-between items-start gap-12'), permitiendo un flujo natural que se apila verticalmente en móviles y se distribuye equitativamente en pantallas amplias.

5. Reutilización de componentes:
   - Se copiaron íntegramente los botones, tarjetas, alertas y formulario desde 'componentes.html', preservando los tokens de diseño (radios rounded-lg / rounded-2xl, espaciados y anillos de foco accesible).

   - Casos de uso: Bootstrap conviene cuando se priorizan componentes estándar, prototipos rápidos o plugins JavaScript listos. Tailwind conviene cuando se necesita una identidad visual propia y se quiere compilar solo las utilidades detectadas; las clases @apply sirven para las variantes repetidas, mientras las cards siguen visibles en el marcado.
